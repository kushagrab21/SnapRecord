## (f) Recommendation — first product packet

**P-002: close-up label capture and extraction fidelity.** Not storage, not a review screen. The one thing this packet could not establish is the one thing the product depends on.

**1. Capture path — the capture page can stay a plain HTTP page served from this laptop; do not build a PWA yet.** Evidence: R-0005, a 2.77MB JPEG crossed from `192.168.100.21` to `192.168.100.104` over plain HTTP in 20 seconds with zero dependencies and no certificate. The `file`-input path needs no HTTPS at all. The pressure toward HTTPS comes only from `getUserMedia`, which the product does not yet need — and R-0006 is the reason to stay on the file input a while longer: `capture="environment"` gave a picker rather than a viewfinder, so an in-page viewfinder is a real future want, but it is the expensive path and should be bought only once label fidelity justifies it.

**2. Schema changes — add two fields, remove none.** Evidence: all three runs populated every required field and `additionalProperties: false` never tripped, so nothing in `item.v0.json` is dead. Two gaps showed up. First, `uncertain_fields` came back `[]` on all three runs while `confidence` sat at 0.80–0.85 — the model expressed doubt globally but never located it, so per-field confidence would be more useful than a single number. Second, R-0011: nothing in the schema records *capture conditions*, yet whether a photo is a close-up or a 3m room shot is exactly what determined the quality of this result; a `capture_quality` or `label_legible` boolean the model sets would let the pipeline reject a shot before spending on extraction. Both are additions to a v1 schema, not changes to v0.

**3. Model and cost — standardise on `google/gemini-3.8-flash` at ~USD 0.0034 per photo.** Evidence: R-0008 and R-0009 — 3 of 3 schema-valid, 7–15s, USD 0.00320/0.00340/0.00373 from OpenRouter's own `usage.cost`. At that price 1,000 photos cost about USD 3.40. Hold this loosely: the cost is dominated by the fixed ~1,450-token image payload, and completion length will rise with dense labels. Re-measure at P-002 on a real label, and compare against one stronger model on the same image before committing, since an OCR error is more expensive than a fraction of a cent.
